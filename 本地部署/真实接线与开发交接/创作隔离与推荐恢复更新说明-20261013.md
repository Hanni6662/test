# 创作隔离与推荐恢复增量更新

日期：2026-10-13。本次同步已经验证的创作流程修复，保留原交付包的可移植启动配置和固定基础镜像版本。

## 修复内容

- 当前创作与历史详情使用独立状态、预览和恢复缓存。历史预览、下载、刷新或重试不覆盖当前推荐、偏好或任务。
- 当前身份可以分页查询推荐阶段的流程，尚未生成、失败和核实中的记录也能在历史看到。恢复其他流程前需先完成或明确结束当前创作。
- 创建真实会话前检查依赖，连接失败时保留参考图并给出明确提示。
- 对已确定请求未发出的连接建立或连接池失败，最多重试三次（5、15、45 秒）；按图片持久化重试动作，保持图片顺序并只启动一次 Dify。写入/读取超时与结果不明仍禁止自动重发。
- 只允许结束服务端确认没有启动动作、run、Task、生成请求、阶段回调或执行中动作的上传 unknown 会话；参考图与审计保留。正常已启动流程不受此入口影响。
- 身份重置隔离旧身份数据，同时后台已开始流程继续。重置身份不能修复后端连接故障。

本包的可移植一键启动脚本已包含完整真实 overlay、健康服务复用与容器间连通性检查，本次原样保留。没有复制开发机目录、网络名称、发布标识或凭证；不新增仅适用开发机的 Dify 快捷方式。

## 接口与运行版本

- `GET /api/v1/business-sessions?limit=20&cursor=...`：按当前身份查询流程历史，排除私有 form token 和提示词。
- `GET /api/v1/business-sessions/readiness`：需要当前身份，检查配置的 Dify/生图服务。
- `POST /api/v1/business-sessions/{id}/end-unstarted`：需要当前身份和同源校验，事务复核未启动条件，可重放。
- v3.4 会话详情新增 `can_end_before_start`，公开投影显示可解释的上传原因。

新的后端标签为 `image-backend:delivery-creation-fix-20261013`，从此开发包的清洁 backend 源码和固定部署 Dockerfile 构建。镜像 ID 以 `images/镜像清单.json` 为准，源码与镜像由 `source-release.json` 验证。随包归档只更新后端镜像，保留原生图服务和插件守护进程镜像。不新增数据库迁移，不升级框架或依赖。

若旧会话仍显示参考图上传结果不确定，可以在当前身份查看处理入口；不能批量将所有 reconciling 会话标成失败，也不能把旧身份记录转移给新身份。
