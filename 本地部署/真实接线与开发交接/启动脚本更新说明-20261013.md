# 一键启动脚本增量更新（2026-10-13）

本次同步启动脚本、前端代理启动检查、相关测试和接收者说明。按源项目目前的行为，默认复用运行中且配置一致的服务，显式 `--restart` 才重启。基础 Compose、固定镜像版本、后端业务代码和原真实流程未修改。本说明中的验证是本次启动脚本验证，此前真实生图与后端修复验收属于历史记录。

## 改动与接收者操作

- 新增 `frontend/一键启动.cmd`、`启动本地工作台.ps1` 和 `scripts/start-workbench.mjs`。启动器按当前启用的 Compose 服务依赖分阶段启动数据库、队列、初始化任务和业务进程，等待健康后才启动前端和打开浏览器。
- 新增 `frontend/workbench.config.example.json`。接收者复制为 `workbench.config.local.json`，填写自己的实例名和配置路径；该本机文件与启动锁均被忽略。相对路径从开发包根目录解析，不依赖原开发机的盘符、实例、网络或运行目录。
- `standalone` 使用自己的已初始化 mock 实例；`chatflow` 必须配置自己的 Dify、真实运行凭证和公开 overlay，不能因缺少配置而自动降级。真实模式从两个 Compose 的配置核对共享网络，按实际发布端口检查生图健康，并检查容器间健康接口。
- 新增 `scripts/workbench.dify.yaml`，为固定版本的 Dify worker/beat 提供进程健康检查。它是独立的可移植 overlay，不复制原开发机禁用健康检查的状态，不覆盖基础 Compose 的镜像和清洁配置。
- `scripts/start-frontend.mjs` 支持 `--require-backend`，在打开浏览器之前检查前端代理的后端就绪状态；新创建的临时前端若检查失败会关闭。
- 完成的迁移、权限和存储初始化容器允许正常退出，不重复执行。已有图片继续使用实例自己的私有数据卷；没有新增对象存储或复制数据库与用户图片。

先按根 README 导入交付镜像、准备标准依赖镜像、初始化自己的实例并配置自己的 `.env.local`。真实模式还需配置 Dify 工作区、`runtime.env`、生图私有环境文件和代理模板，复制 `chatflow/image-generation/.env.example` 为该目录的 `.env` 以满足基础 Compose 的 env_file 定义。Key 只存服务端。随后运行：

```powershell
Set-Location '<开发包目录>/frontend'
Copy-Item -LiteralPath './workbench.config.example.json' -Destination './workbench.config.local.json'
# 编辑自己的实例名和路径，再检查
& './启动本地工作台.ps1' -Check
& './一键启动.cmd'
# 只有需要重启时使用；先等待正在执行的任务结束
& './启动本地工作台.ps1' -Restart -NoOpen
```

无需新增数据库迁移、重新初始化已有实例或重新构建镜像。脚本不自动构建、拉取或删除运行镜像，也不清理接收者已有容器、网络和数据卷。首次创建前端时需保持启动窗口打开。
